# Changelog & Algorithmic Provenance

All notable changes, algorithmic bug fixes, and methodology updates to the RadNet Anomaly Detection Benchmark are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-10-31

### Changed
- **Terminology Migration (Physics-Motivated)**: Renamed "Physics-Informed" to "Physics-Motivated" across manuscript text, tables, figures, code constants, and evaluation scripts (`TIER_4_CANONICAL_NAME = "Tier 4 (Physics-Motivated Nuclear)"`).
- **Backward Compatibility Aliases**: Provided automatic translation mapping via `TIER_NAME_ALIASES` and `canonicalize_tier_name()` in `src/feature_engineering.py` so that existing scripts and legacy CSV data containing `"Tier 4 (Physics-Informed Nuclear)"` resolve seamlessly to canonical `"Tier 4 (Physics-Motivated Nuclear)"`.
- **Rule-Based Alarm Categorization**: Clarified that clean-background test alarm categorization ($N=100$) was generated by automated, deterministic decision-tree rules in `src/adjudicate_clean_alarms.py` rather than subjective manual review.

### Added
- **Real-Event Benchmark Evaluation**: One-shot evaluation on Fukushima Daiichi trans-Pacific plume (March–April 2011) across Pacific gateway stations (Honolulu, San Diego, Anchorage) and continental control (Dallas).
- **Rule-Based Alarm Categorization Audit**: Automated categorization of $N=100$ clean-background test alarms into meteorological and operational categories with Wilson score 95% confidence intervals.
- **Extended Stations & Cross-Climate Generalization**: Evaluated 6 additional stations across 5 Köppen climate classes; diagnosed Tampa 2023 PMT/detector hardware step-change; implemented causal 168h rolling normalization and local historical calibration.
- **Bootstrap Uncertainty & Operating Points**: Station-month block bootstrap and plume cluster bootstrap replacing naive seed p-values; clean validation false-alarm budget operating points ($1, 2, 5, 10, 20\text{ FA/yr}$).
- **Stronger Baselines & Ablations**: Implemented Non-ML B4c Radon Projection, B5b Background NMF, B6c One-Class SVM, B7a Supervised Logistic Regression, and feature tier ablations.
- **Realistic Monte Carlo Detector Response**: Replaced synthetic generator artifacts with Geant4/MCNP6 photon transport templates, arbitrary filter termination, and physical Poisson counting noise.
- **Data Manifest & Reproducibility**: Automated `data/DATA_MANIFEST.csv` hashing 254 input/derived files; Dockerfile; CI workflow; Zenodo archive.

## Historical Code Improvements & Bug Fixes Provenance

During initial development leading up to the October 2026 benchmark freeze, twelve targeted methodological and numerical fixes (designated Issues #1 through #12) were implemented to ensure strict causal hygiene, eliminate data leakage, and ensure numerical stability. Their provenance, dates, and quantitative effects on benchmark results are recorded below:

### Issue #1 - Enforce strict train/val/test fold separation (2026-10-06)
- **Files**: `src/train_and_evaluate_models.py`, `src/train_and_evaluate_rigorous.py`, `src/evaluate_uncertainty_protocol.py`
- **Issue**: Initial prototype allowed feature normalizers and threshold selection to access the full 2017–2022 dataset simultaneously, creating subtle temporal lookahead leakage between training and validation.
- **Fix**: Enforced strict fold separation: model fitting occurs strictly on 2017–2020 (`train` fold); decision threshold selection ($\tau$) occurs strictly on 2021–2022 (`validation` fold); 2023–2025 (`test` fold) remains completely held out.
- **Effect on Results**: Eliminated optimistic validation bias. Shifted validation-selected thresholds slightly higher ($\tau \approx 0.70 \to 0.87$), ensuring clean test false alarm rates match operating budgets.

### Issue #2 - Edge-case threshold fallback logic (2026-10-06)
- **Files**: `src/train_and_evaluate_rigorous.py`
- **Issue**: When an operating detection target (e.g., 98% detection) was mathematically unreachable on the validation fold, the threshold search fell back to `.iloc[-1]`, which corresponded to the lowest-detection / highest-threshold edge case.
- **Fix**: Implemented explicit fallback to the maximum achievable validation detection point, and flagged unreachable operating targets in summary outputs.
- **Effect on Results**: Prevented baseline detectors with low SNR sensitivity from collapsing to zero detection at aggressive operating targets.

### Issue #3 - Missing weather telemetry tolerance in filter cycles (2026-10-06)
- **Files**: `src/analyze_filter_cycles_multi_station.py`
- **Issue**: Missing precipitation telemetry (`NaN` values in NOAA records) was previously treated as non-dry in filter advance detection guards, discarding legitimate filter change step drops adjacent to brief weather telemetry outages.
- **Fix**: Adjusted filter drop candidate filter to tolerate unrecorded rain at $t-1, t-2, t-3$ while requiring verified zero rain at $t$, preventing false discard of maintenance steps.
- **Effect on Results**: Increased detected filter step-drop sample size by ~22%, providing robust empirical estimates of station-specific filter tape advance cycles.

### Issue #4 - Training-only baseline computation (2026-10-06)
- **Files**: `src/synthetic_injection.py`, `src/compute_train_only_baselines.py`
- **Issue**: Dry baseline CPM estimates ($\mu_{dry}, \sigma_{dry}$) used for heuristic radon washout labeling were computed over the entire 2017–2025 timespan, introducing forward-looking leakage into training set labels.
- **Fix**: Refactored `compute_train_only_baselines.py` to compute station dry baselines strictly on the 2017–2020 fit fold.
- **Effect on Results**: Enforced strict zero-leakage training. Dry baseline shifts between 2017–2020 and 2023–2025 now properly reflect empirical environmental drift.

### Issue #5 - Rolling history warm-up buffers (2026-10-06)
- **Files**: `src/evaluate_uncertainty_protocol.py`, `src/feature_engineering.py`
- **Issue**: Prepending insufficient rolling history prior to the validation split boundary ($2021\text{-}01\text{-}01$) caused rolling 168-hour statistics to have `NaN` values for the first 7 days of validation.
- **Fix**: Full continuous time series are computed with warm-up buffers prior to fold slicing.
- **Effect on Results**: Restored 168 hours of valid evaluation data per station fold, eliminating edge truncation artifacts.

### Issue #6 - Episode counting across calendar boundaries (2026-10-06)
- **Files**: `src/train_and_evaluate_rigorous.py`
- **Issue**: Counting consecutive alarm hours across month boundaries previously caused single multi-hour alarm episodes to be double-counted if they spanned midnight of the last day of the month.
- **Fix**: Episode starts ($t$ where $alarm_t = 1$ and $alarm_{t-1} = 0$) are identified on the unbroken time series before assigning episodes to calendar months.
- **Effect on Results**: Reduced false alarm episode counts by ~1.2%, strictly adhering to episode-based alerting standards.

### Issue #7 - Analytical matrix exponential for Bateman washout ODE (2026-10-06)
- **Files**: `src/synthetic_injection.py`
- **Issue**: Bateman washout ODE integration used forward Euler discretization with fixed 1-hour step size, producing numerical overshoot during intense rain bursts ($>30\text{ mm/h}$).
- **Fix**: Implemented analytical matrix exponential solution for the 3-stage coupled decay chain ($^{218}\text{Po} \to {}^{214}\text{Pb} \to {}^{214}\text{Bi}$).
- **Effect on Results**: Exact numerical stability regardless of rain intensity, matching physical Bateman decay invariants.

### Issue #8 - Filter step-drop deduplication window (2026-10-06)
- **Files**: `src/analyze_filter_cycles_multi_station.py`, `src/characterize_baseline_cycles.py`
- **Issue**: Deduplication of consecutive candidate filter drops compared each candidate to the immediately preceding candidate (which might have been rejected), failing to suppress multiple triggers from a single slow filter transition.
- **Fix**: Each candidate drop is evaluated against the timestamp of the last *retained* step drop, enforcing a strict 24-hour separation window.
- **Effect on Results**: Eliminated clustered duplicate filter change events, ensuring clean Poisson-distributed filter advance intervals.

### Issue #9 - Epsilon floor for low-energy photopeak ratios (2026-10-06)
- **Files**: `src/feature_engineering.py`
- **Issue**: Relative photopeak ratios ($R_{05}/R_{03}$, $R_{02}/R_{03}$) suffered division-by-zero spikes when low-energy channels had zero counts during detector brownouts.
- **Fix**: Added protective $\epsilon = 10^{-4}$ denominator floor.
- **Effect on Results**: Replaced infinite feature values with bounded ratios, preventing numerical divergence in GBDT splits.

### Issue #10 - Alignment of ICRP-74 ambient dose equivalent conversion (2026-10-06)
- **Files**: `src/nuclear_physics.py`
- **Issue**: ICRP-74 ambient dose equivalent conversion coefficients were indexed by channel boundary rather than channel centroid energy.
- **Fix**: Aligned $h^*(10)$ conversion coefficients strictly with channel geometric centroids ($0.15, 0.35, 0.625, 0.875, 1.125, 1.375, 1.75, 2.50\text{ MeV}$).
- **Effect on Results**: Corrected channel energy weighting to within $<0.8\%$ of published ICRP-74 benchmark values.

### Issue #11 - Explicit baseline file verification (2026-10-06)
- **Files**: `src/feature_engineering.py`
- **Issue**: Fallback logic silently substituted arbitrary national average constants when station-specific dry baseline JSON entries were missing.
- **Fix**: Replaced silent substitution with an explicit `KeyError` requiring precomputed station baseline files.
- **Effect on Results**: Prevented accidental ungrounded baseline evaluations during multi-station extensions.

### Issue #12 - Disambiguation of baseline model nomenclature (2026-10-06)
- **Files**: `src/evaluate_baseline.py`
- **Issue**: Misleading duplicate naming where rolling gross count $Z$-score and static dry baseline $Z$-score were both labeled as "Baseline 1".
- **Fix**: Disambiguated into distinct baseline nomenclature: B1 (Global Dry $3\sigma$) and B2 (Rolling 168h $3\sigma$).
- **Effect on Results**: Clean, un-confused benchmark reporting across all tables and figures.
